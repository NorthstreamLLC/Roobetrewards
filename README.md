# roobetcasinorewards.com — Design & Architecture Brief

**Purpose of this doc:** hand it to Claude Design (or any designer) so they can redesign pages
without breaking the live data, SEO or deploy pipeline. Everything a redesign must preserve is
listed under **"Contract"** below.

---

## 1. What this site is

The official rewards hub for **DailyGambling** on **Roobet** — leaderboards, rewards, guides,
live stream and raffles. Affiliate codes: **DAILY** (primary) and **ELITE** (secondary).

- **Live:** https://roobetcasinorewards.com
- **Repo:** github.com/NorthstreamLLC/Roobetrewards
- **Host:** Vercel (auto-deploys on push to `main`)
- **Analytics:** GA4 `G-4XLL2RYBWD`

### Stack

| Layer | What it is |
|---|---|
| Pages | Static HTML, generated by `build.py` (Python, no framework, no build step beyond running it) |
| Styling | One stylesheet: `css/style.css` (CSS variables, no Tailwind, no preprocessor) |
| Behaviour | One script: `js/main.js` (vanilla JS, no dependencies) |
| Backend | Vercel serverless functions in `api/` (Node) |
| Storage | Upstash Redis (raffle entries + OAuth sessions) |

**Important:** never edit the `.html` files directly — they are generated. All content and page
structure lives in `build.py`; run `python3 build.py` to regenerate all pages.

## 3. Current design language

Dark, neon-casino: deep purple background, gold as the reward/action colour, purple as the
accent. Font: **Outfit** (400/600/700/800). Motion: scroll-reveal, animated counters, hover tilt
on cards, pulsing CTAs, glowing background orbs.

```css
--bg:#0d0919        /* page background */
--bg2:#161028       /* gradient partner */
--card:#1a1230      /* card background */
--gold:#ffc700      /* primary action / reward colour */
--gold2:#ffb400
--purple:#7b5cff    /* accent, borders, glows */
--text:#f4f1ff
--muted:#a89fc7     /* secondary text */
--green:#3ddc84     /* live/success */
--radius:18px
--nav-h:72px
```

A redesign may replace all of this freely — **as long as the contract in §5 is honoured.**

## 4. Live/dynamic features (what actually moves)

| Feature | Endpoint | Notes |
|---|---|---|
| Leaderboard top 100 | `GET /api/leaderboard` | Merges every configured Roobet affiliate code (DAILY, ELITE, +) server-side, masks usernames, 5-min cache. Returns `{entries:[{rank,username,wagered}],updated}` |
| Live stream status | `GET /api/live` | Official Kick API via app credentials. Returns `{live:true|false|null}` |
| Raffle | `GET/POST /api/raffle` | View/enter (player) + create/draw (admin key) |
| Kick login | `/api/kick/login` → `/api/kick/callback` | OAuth 2.1 + PKCE, session cookie `rr_sess`, Redis-backed |

**Env vars (set in Vercel, never in code):**
`LEADERBOARD_API_URL`, `LEADERBOARD_API_KEY_<CODE>` (+ optional `LEADERBOARD_API_URL_<CODE>`),
`KICK_CLIENT_ID`, `KICK_CLIENT_SECRET`, `RAFFLE_ADMIN_KEY`, `KV_REST_API_URL`, `KV_REST_API_TOKEN`.

## 5. ⚠️ CONTRACT — what a redesign must preserve

Markup may change completely, but **these hooks must survive** or live features silently break.
`js/main.js` looks for exactly these.

### IDs

| ID | Used for |
|---|---|
| `#lb-table`, `#lb-body` | leaderboard table + tbody (rows injected) |
| `#lb-wrap` | scroll container; gets `.open` when expanded |
| `#lb-toggle` | "Show Full Top 100" button |
| `#lb-search` | player search input |
| `#lb-updated` | "Live · updated HH:MM" stamp |
| `#standings` | scroll target when collapsing |
| `#live-pill` | nav LIVE badge; gets `.on` when live |
| `#watch-status` | watch page status line; gets `.is-live` |
| `#stream-frame` | stream embed container (its presence = "this is the watch page") |
| `#promo-modal` | entry pop-up (needs a `.modal-x` close button inside) |
| `#raffle-widget` + `#rf-title`, `#rf-info`, `#rf-actions`, `#rf-meta` | raffle card on `/giveaways` |

### Attributes / classes

| Hook | Behaviour |
|---|---|
| `.rv` (+ `.d1`–`.d4`) | scroll-reveal animation; must start hidden, `.on` added when visible |
| `[data-count="50000"]` `[data-prefix]` `[data-suffix]` | animated number counters |
| `[data-deadline="monthly\|weekly\|daily\|period16"]` | live countdown text |
| `[data-pod="1\|2\|3"]` | podium slots — top-3 names injected |
| `.mile` + `.bar i[data-w]` | animated progress bars |
| `.flip` (+ `.flip-inner`, `.face.front`, `.face.back`) | point-shop flip cards |
| `.card` | hover tilt |
| `.burger` + `.nav-links` (`.open`) | mobile menu |
| `.dropdown > button` (`.open` on parent) | rewards dropdown |
| `.live-toast` (+ `.toast-x`) | live notification toast (JS-created; style only) |

### Also preserve

- One `<script type="application/ld+json">` per page containing the `@graph` (WebSite → Organization
  → WebPage → BreadcrumbList → page entity). Generated automatically — don't hand-write it.
- The GA4 tag immediately after `<head>`, exactly once per page.
- `rel="nofollow sponsored"` on every `roobet.com/?ref=` link.
- The 18+ / responsible-gambling footer block.
- Affiliate hierarchy: **DAILY is the primary code**, ELITE secondary.

## 6. Working with Claude Design — can I transfer it over?

**Yes.** Claude Design outputs self-contained HTML/CSS; porting it here is a translation job, not a
rebuild. The cleanest workflow:

1. **Design one page at a time**, starting with the homepage or `/leaderboard`. Give Claude Design
   this doc plus the live URL for reference.
2. **Ask it for static HTML + CSS in one file**, using CSS variables for colour/spacing, and to
   keep the hooks from §5 wherever the corresponding feature appears (or just leave placeholders
   named the same — e.g. an empty `<tbody id="lb-body">`).
3. **Send the result back to me here.** I port it into `build.py` (structure) and `css/style.css`
   (styling), re-wire the live data, regenerate all 30 pages so the new look applies sitewide,
   and push.

**Don't** paste designed HTML straight into the `.html` files — the next `build.py` run overwrites
them. Everything goes through the generator.

**Best-case handoff:** design the *system* (colours, type scale, buttons, cards, tables, nav,
hero) plus 2–3 representative pages. Then a single pass applies it to all 30 pages consistently.

## 7. Deploy

```
edit build.py / css / js  →  python3 build.py  →  git add -A
→ git commit -m "…"  →  git push origin main  →  Vercel auto-deploys (~10s)
```

GitHub access uses a fine-grained PAT scoped to this repo (Contents: read & write). Tokens expire —
regenerate at github.com/settings/personal-access-tokens when pushes start failing.
